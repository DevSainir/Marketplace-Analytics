# Journal of finished work

What was done in the project, one row per task — from a small fix to a large feature.
Newest rows on top. How to add a row is in the `git-workflow` skill, section
"The journal of finished work".

The script `scripts/journal_page.py` checks that the rows are well-formed
(`python3 scripts/journal_page.py --check`) and builds a single-page HTML view
with filters from this file (`python3 scripts/journal_page.py --out <path>/journal.html`).
Ready-made views open from a link with a tag: `#week`, `#month`, `#quarter`,
`#month-pnl`, `#week-infra` (areas: `monitoring`, `pnl`, `ads`, `ab`, `summary`,
`heatmap`, `ui`, `access`, `infra`, `security`, `process`).

Rows up to 2026-10-17 were reconstructed from the commit history: every `fix`, `feat`,
`feat-minor` and `perf` commit since 2026-07-09 was grouped into tasks.

Columns:

* **Date** — the day the task was finished (its last commit), `YYYY-MM-DD`.
* **Task** — what was done, briefly and in plain words.
* **Area** — one of: Monitoring, P&L, Advertising, A/B tests, Summary, Heatmap, UI,
  Access, Infrastructure, Security, Process.
* **Type** — one of:
  * feature — something new that did not exist before;
  * improvement — something that existed became more convenient, accurate or faster;
  * bug — a fix for something that was already supposed to work;
  * infrastructure — servers, deploys, backups, alerts, tests;
  * docs — docs, skills, working rules.
* **Size** — S (a few hours), M (a day or two), L (a week or a large feature).
* **Why** — one line: what the problem was, or what it gives people.
* **Commits** — short hashes of the main commits, separated by spaces; may be empty.
